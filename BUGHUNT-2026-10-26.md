# Bug hunt, 2026-10-26

Two rounds, six read-only audits. **No code changed.** Items marked ✔ I checked in the code myself. The rest are the auditors' findings (C = traced or reproduced, P = plausible).

**Headline:** nothing lets anything outside your user account in. The bridge's Origin, Host, content-type and token checks held against everything tried. The `/rpc` allowlist matches the plugin's. Game scripts and free models can't reach the playtest bus or `_G.__CUBES_MCP`. The real problems are in the confirm/safety layer and in robustness.

## Low

- **Bridge:**
  - The token is printed to stderr, which MCP clients log.
  - ws keeps its default 100 MiB `maxPayload`.
  - `writeEnabled` is one global shared by all Studio windows (each plugin still gates on its own).
  - IPv6 `[::1]` Host is always refused (`bridge.ts:1089` splits on the first `:`).
- **Safety labels:**
  - Nuclear misses service spellings like `game`, `.ServerScriptService` and `TextChatService`.
  - `set Archivable=false` is rated soft.
  - The activity label can make a destructive batch read as "Building".
  - Prompt text can be spoofed through newlines in `name` or `target`.
- **Disk:**
  - `mesh_export` overwrites files with writes off.
  - NTFS alternate data streams (`x.txt:s.glb`) are accepted.
  - Script-history blobs are written non-atomically.
  - Screenshots too big to send are left in TEMP.
- **Plugin:**
  - A non-table poll body kills the loop while the panel still shows online.
  - EditableMesh isn't freed when a bake fails.
  - `mesh_build` parents with no undo waypoint.
  - `set` still works on refs to children of a deleted instance.
  - Writes are on by default at install.
  - `camera_set`, `viewport_capture` and `raycast fromCamera` use the server camera during play.
  - The panel reopens on every reconnect.
  - The Activity tile never shows "Playtest".
  - `capture` is on the read-only list but has no handler.
- **Other:**
  - On Windows, lint can run a planted `selene.exe` from `CUBES_MCP_LINT_CWD`.
  - The PowerShell quoting only escapes the ASCII `'`.
  - `@hono/node-server` audit advisory (it isn't reachable).
  - The CI workflow has no `permissions:` block.
  - `macro_run` and `script_restore` wrap errors so they look like success.

## Suggested fix order

1. #1 and #10: only the human's elicitation answer counts as consent when the client supports it.
2. #2 and #3: an unresolvable ref is an error; rate `Parent` sets as hard; strip `@` before both the history check and the service check.
3. #4: add a per-load nonce to refs (e.g. `p3.k7f`) so stale ones fail as `ref_dead`.
4. #5 (a one-line fix), #7 (cap or replace the regex), #8 (check accessor counts against the buffer, and cap node visits).
5. Then #6, #12–#17.
