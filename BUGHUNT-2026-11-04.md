# Bug hunt, 2026-11-04

**Status: findings 1 to 10 are fixed, with tests where they can run without Studio.** The "Smaller" list is not fixed. Plugin-side fixes (1, 2, 9, 10) need a Studio restart to load. What follows is the audit as written.

The audit itself changed no code. Run against the uncommitted tree: `player_input`, `ui_inspect` and the bus resend logic are not committed yet. Two read-only auditors covered what the last hunt skipped, and I checked each listed finding against the code.

**Confirmed** means it was run and seen failing. **Likely** means traced end to end but not run.

## Worst first

### 1. Rotated CFrames are corrupted when written back: `plugin/src/Mutate.luau:23`
- **Breaks:** a part gets a wrong rotation and position data, and the mutate reports success. Vector3 values with very small components have the same problem.
- **Trigger:** read a part rotated 90 degrees, then send that value back with `set CFrame`.
- **Why:** `-?%d*%.?%d+` doesn't understand exponents, so `-4.37113883e-08` becomes `-4.37113883` and `-8`. The `#n >= 12` check still passes on the 14 numbers and uses the wrong first 12.
- **Confidence:** confirmed in Studio up to the parse: `__MCP.serialize` returned the exponent form and the same pattern produced 14 numbers. The write itself was not run, to leave the place alone.
- **Fix:** an exponent-aware pattern, and exactly 12 or 3 numbers for a CFrame.

### 2. A path segment named `game` or `DataModel` is skipped at any depth: `plugin/src/Refs.luau:80`, `:151`
- **Breaks:** `delete Workspace.Map.game` destroys `Workspace.Map`, whether or not such a child exists. A real child with that name can't be reached either.
- **Trigger:** any target with that segment below the root.
- **Confidence:** confirmed in Studio, read-only: `__MCP.resolve("Workspace.game")` returned `Workspace` with no such child present.
- **Fix:** only skip those names when `node == game`, at both sites.

### 3. A failed camera turn leaves the right mouse button stuck: `src/tools/playtest.ts`, `look` (new, uncommitted)
- **Breaks:** every later `look` fails with "duplicate button state" until the playtest restarts.
- **Trigger:** `look` with a GUI button under the centre of the screen. The button takes the press, the cursor doesn't lock, and `SendMouseDelta` throws "cursor is not locked" before the release.
- **Also:** `look` holds the button at screen centre, so it can press whatever menu is there.
- **Confidence:** confirmed live.
- **Fix:** always release in a `pcall`, and press at a spot with no GUI under it, or return a clear error if there's none.

### 4. A huge camera turn runs past the time limit: `src/tools/playtest.ts`, `look` (new, uncommitted)
- **Breaks:** the call reports a timeout while the turn keeps running in the background, with the right button held and new input mixing into it.
- **Trigger:** `{do:"look", dx:60000}`. The time check counts 0.3s; it takes about 60s.
- **Confidence:** confirmed live: `bus_timeout` after 20s, right button still down, and a following walk ran during it.
- **Fix:** cap the number of steps, or size each step to the time allowed.

### 5. Viewport screenshots are cropped too small: `src/vision.ts:249`, `:258`, `:273`
- **Breaks:** the right and bottom of the 3D view are cut off. A 1200x700 viewport found at (300,150) comes back 900x550.
- **Why:** PowerShell variables ignore case, so `$w`/`$h` overwrite the window size in `$W`/`$H`, and line 273 then subtracts the offset from the crop.
- **Confidence:** confirmed by running those lines in PowerShell with mock values.
- **Fix:** rename the window size to `$winW`/`$winH`.

### 6. A failed screenshot sends your whole monitor: `src/vision.ts:557`
- **Breaks:** with Studio closed or its window too small, a normal `screenshot` returns the entire desktop to the model, with only a `warning` field saying so. Whatever else is on screen goes with it.
- **Confidence:** likely. Not run, on purpose, to avoid capturing the desktop.
- **Fix:** return an error for any failure unless `full` was asked for.

### 7. `profile_update` loses data: `src/tools/session.ts:125`, `:149`, `src/profile.ts:96`
- **Breaks:** 10 parallel updates kept 1 of 10 entries and 4 failed outright. A corrupt profile file is overwritten on the next save, wiping the decisions log, though its comment says the file is kept.
- **Why:** the tool calls load and save directly. `updateProfile`, the safe version, has no callers outside tests.
- **Confidence:** confirmed through the tool handler.
- **Fix:** call `updateProfile`, and rename a corrupt file to `.corrupt` before starting fresh.

### 8. A small mesh file can crash or freeze the server: `src/mesh.ts:234-337`, `:512-521`
- **Breaks:** `mesh_import` takes the MCP server down or blocks it, and Studio's link stalls with it.
- **Trigger:** a 64 MB OBJ of `f 1 2 3` lines parsed to 25M vertices, blocked 15.7s and used over 2 GB. A 66 MB OBJ with one huge face line aborted Node, but that is just over the 64 MB limit. A crafted GLB blocked for 2s, and the cost grows with file size.
- **Why:** `parseObj` never checks the parse caps, and `parseGlb` only caps POSITION and indices.
- **Confidence:** confirmed for those runs. The crash inside the limit was not run.
- **Fix:** apply the caps while parsing the OBJ, and a total accessor budget in the GLB.

### 9. A resend can run a command twice in two cases: `plugin/src/PlaytestBus.luau` (new, uncommitted)
- **Breaks:** a `client_eval` or `tune` runs a second time, which is what the resend was meant to rule out.
- **Trigger, case 1:** Stop then Play by hand in Studio while a command is waiting: the new playtest's bus has no memory of it.
- **Trigger, case 2:** a multi-player test where the plain `client` inbox changes owner mid-command. Passing `player` avoids this.
- **Confidence:** likely. Traced only.
- **Fix:** stop resending once the bus has gone quiet for about 2s, and record taken ids in a setting that all clients can read.

### 10. An open undo recording can block later writes: `src/tools/instances.ts:318-334`, `:254-279`
- **Breaks:** if the tool's Luau throws between `beginUndo` and `endUndo`, the recording never closes. `Mutate.luau:386` may then refuse every batch with `no_undo_available`.
- **Trigger:** `particle_emitter_add {target:"<part>", lifetimeMin:5}`, because `lifetimeMax` defaults to 1. `NumberRange.new(5,1)` should throw.
- **Confidence:** likely. Not run, to avoid leaving your open place in that state.
- **Fix:** run those bodies through a wrapper that always finishes the recording, as `__MCP.waypoint` already does, and clamp min and max.
